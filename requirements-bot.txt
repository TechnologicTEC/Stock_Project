# Deps for the scheduled trading bot (scripts/run_bot.py) in CI.
#
# Deliberately the smallest of the requirements files. The bot places orders and
# reads cached prices — it renders nothing and scores nothing, so there's no
# Streamlit stack, no torch/transformers (FinBERT), and no BigQuery. The screener
# strategies read the leaderboard that the weekly screen job already wrote to the
# shared cache, rather than re-screening the index themselves.
sqlalchemy>=2.0
psycopg2-binary>=2.9
alpaca-py>=0.30          # paper trading + the price history the bot reads
pandas>=2.2              # engine/price_history returns frames
numpy>=2.0               # pandas' own dependency; also engine/health metrics
# Pure-python TA. Here so golden_cross can import engine/backtest's own
# _signal_sma_cross instead of reimplementing the 50/200 rule: the point of that
# strategy is that the live bot and the backtest must compute the identical
# thing, and a second copy of the formula would quietly break the comparison.
pandas-ta-classic>=0.6

# Not optional, despite the bot reading prices from Alpaca and never calling
# either of these. engine/price_history imports yfinance_client at module level
# and engine/screener imports finnhub_client, so both packages must be
# importable or the job dies on `import`, not on use. Verified by simulating
# this file's environment: without yfinance, price_history and screener both
# fail to import; without finnhub, screener does.
yfinance>=0.2            # engine/price_history's module-level import
finnhub-python>=2.4      # engine/screener's, via engine/data_sources
# Needed by creator_conviction, and it fails LATER than the two above rather
# than at import: engine/creator_signals imports youtube_client, which imports
# BeautifulSoup at module level to scrape the channel feed. The bot reads
# mentions back out of the database and never scrapes anything, so nothing here
# calls bs4 — and because the strategy defers its creator_signals import into
# prepare(), the module loads fine and the run dies mid-flight with a
# ModuleNotFoundError once it reaches out for the mention window. Confirmed by
# uninstalling it from a venv built off this file: creator_signals stops
# importing, creator_conviction does not.
beautifulsoup4>=4.12
python-dotenv>=1.0
requests>=2.31
